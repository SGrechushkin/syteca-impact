# Syteca impact → TestRail run

**Що це:** інструмент для QA, який за імпактом задачі з Jira автоматично збирає тест-ран у TestRail.
Замість ручного пошуку серед ~38 000 кейсів ви даєте посилання на тікет — Claude Code (AI-асистент у VS Code) знаходить кейси, що покривають імпакт і суміжні флоу, прибирає дублі та, якщо покриття немає, пропонує нові кейси. Нічого не створюється без вашого підтвердження.

Пишете в Claude Code `/impact AC-12345` (або даєте .md-файл з імпактом) → Claude читає поле **Impact_Ekran** у Jira (або файл), підбирає кейси в TestRail (P1/P2/P3), показує дублі, застарілі кейси й непокриті сценарії (з чернетками нових кейсів) → після вашого «ок» створює ран і дає посилання.

TestRail: проєкт **AI: CSM2** (project 9, suite 13 "Master").

**Що в папці:**

| Шлях | Призначення |
|---|---|
| `CLAUDE.md` | Правила для Claude: як підбирати кейси, як писати нові (спільні для команди) |
| `.claude/skills/impact/` | Команда `/impact` (один або кілька тікетів) |
| `.claude/skills/presending/` | Команда `/presending` (скоуп версії за JQL → пресендінг-ран) |
| `.claude/settings.json` | Дозволи: пошук і читання без підтверджень, зміни в TestRail — лише з підтвердженням |
| `scripts/` | Python-скрипти: синхронізація кейсів, пошук, читання Jira, створення ранів і кейсів |
| `data/` | Локальна копія кейсів TestRail (створюється `sync.py`, не в git) |
| `runs/` | Ваші списки кейсів для ранів і чернетки нових кейсів (не в git) |

## Встановлення (один раз, ~10 хв)

1. **Python 3.12+** — https://www.python.org/downloads/windows/ → у першому вікні інсталятора відмітьте **Add python.exe to PATH**.
   Перевірка: `py --version`
2. **VS Code → Extensions (Ctrl+Shift+X) → Claude Code** (Anthropic) → Install → увійдіть у свій акаунт Claude.
3. **Проєкт і бібліотеки** (PowerShell, у папці, де зберігаєте проєкти):
   ```
   git clone https://jira.dev.local/bitbucket/scm/~viktor.kustovskyi/syteca-impact.git
   cd syteca-impact
   py -m pip install -r requirements.txt
   ```
4. **Логіни TestRail і Jira** — зберігаються в Диспетчері облікових даних Windows, не у файлах:
   ```
   py -X utf8 scripts/set_credentials.py testrail
   py -X utf8 scripts/set_credentials.py jira
   ```
5. **Перевірка й перше завантаження кейсів** (~38 000 кейсів, кілька хвилин):
   ```
   py -X utf8 scripts/check_connection.py
   py -X utf8 scripts/sync.py
   ```
   Має вивести `Project 9: AI: CSM2` і `Suite 13: Master`. Далі Claude сам оновлює базу перед кожним аналізом: завантажує лише змінені кейси (кілька секунд), раз на тиждень — повністю.

## Використання

1. VS Code → **File → Open Folder** → `syteca-impact` → відкрийте панель Claude Code.
2. Напишіть:
   ```
   /impact https://jira.dev.local/jira/browse/AC-12345
   ```
   Кілька тікетів в один ран зі своєю назвою: `/impact AC-1 AC-2 — один ран, назва "ETR-1 - regression"`

   Замість посилання можна дати **.md-файл з імпактом** (наприклад, якщо імпакту ще немає в Jira): перетягніть файл у чат Claude Code або вкажіть шлях:
   ```
   /impact C:\impacts\openssl-update.md
   ```
   Текст файлу — це імпакт. Якщо у файлі є ключ Jira, Claude також прочитає тікет для контексту. Назва рану — ваша, інакше перший заголовок файлу.
   **Пресендінг для версії** — дайте вибірку тікетів (посилання з JQL чи фільтром або сам JQL):
   ```
   /presending https://jira.dev.local/jira/issues/?jql=project%20%3D%20AC%20AND%20fixVersion%20%3D%207.28.320 ETR-13819
   ```
   Claude відкриє кожен тікет вибірки, згрупує скоуп за командними версіями (PAM_H_2026_17, PEDM_HOTFIX_10…), прочитає Impact_Ekran, опис і коментарі та окремо покаже імпакт, якого розробники не вказали (🔴/🟠/🟡). Потім збере ран «Pre-sending testing <версія>»: обов'язкову базу з `Hot_fixes- Pre-sending` під платформи зі скоупу, основний функціонал змінених областей і кейси під ризики. Звіт збережеться в `runs/presending-<версія>.md`. Можна дати посилання на попередній пресендінг-ран, щоб базу взяли з нього.
3. Правте звичайними словами: «прибери надлишкові», «об'єднай в один end-to-end кейс», «додай кейс на ...».
4. **«ок»** — лише після цього Claude створює ран / нові кейси в TestRail.
5. Якщо після створення ви самі змінили ран у TestRail — напишіть Claude «я поправив ран»: він порівняє зі своїм варіантом, запитає про незрозумілі зміни й запропонує нові правила в `CLAUDE.md`.

Оновлення проєкту: `git pull` у папці проєкту.

## Правила (`CLAUDE.md`, спільні для команди — змінюйте через pull request)

- Ран будується за полем **Impact_Ekran**, а не за описом бага.
- Без надлишкових кейсів: один кейс — одна перевірка.
- Нові кейси: тільки в наявні папки за змістом, англійською, у стилі сусідніх кейсів, end-to-end, варіанти — в ER.
  Тайтл: `<Area> - <precondition> - <steps> - Check that ...` (до 250 символів).
- Наявні кейси ніколи не редагуються й не видаляються.
- Нічого не створюється в TestRail без вашого явного «ок».

## Що не потрапляє в репозиторій

`data/` (локальна копія кейсів, ~60 MB), `runs/` (ваші списки ранів і чернетки), `.claude/settings.local.json`, логіни/паролі.

## Якщо не працює

| Помилка | Рішення |
|---|---|
| `'py' is not recognized` | Перевстановіть Python з **Add python.exe to PATH** |
| `No module named ...` | `py -m pip install -r requirements.txt` |
| `No credentials ... syteca-testrail` / `HTTP 401` | `py -X utf8 scripts/set_credentials.py testrail` (або `jira`) |
| `CERTIFICATE_VERIFY_FAILED` | Перевірте VPN / корпоративну мережу і що встановлено `truststore` |
| Таймаут / HTTP 500 при створенні кейсів | Повторіть ту саму команду — скрипт знайде вже створені кейси, дублів не буде |
